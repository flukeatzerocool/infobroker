## Done bar

**Non-closure rule:** a P0 that cannot be fixed inside D33's bound stops the chunk. The AAR then ends `LOOP OPEN`, the roadmap trigger stays on R4, and the done bar is not claimed.

## Scope

**In scope.** The `fetch_page` request path and its supporting modules: URL intake and the URL guard at every hop, renderer selection and the race/fallback chain, anti-bot challenge detection and fall-through, failure classification and DOI/open-access/archive fallback, the knowledge-base read-through cache, date detection, bounded same-origin crawl, structured metadata extraction (JSON-LD/OpenGraph/microdata), question-grounded passage ranking, raw-text response mode, array/batch merge and per-input metadata, the truncation **state reported in `REQ-021j`/`REQ-021k` metadata** (the truncation mechanism itself is `REQ-004`, R1-owned), `structured_fact` classification and the fact object surfaced by `search_web`, the `fetch_page` handler's envelope metadata **only where `REQ-021j`/`REQ-021k` require it**, the registration schema, the `fetch_page` entry in `src/intent-citations.ts` (no other routing row), and §6.4 prose.

**Out of scope.** Provider result parsing and registration for search providers (R2 closed). `search_web` routing, reconciliation, deep reading, research, and analysis (R3 closed; R4 reads `src/index.ts` `search_web` only where `REQ-021i` facts are emitted). Corroboration, citation-grade snapshots (`src/preservation.ts`, REQ-122) and source modality (`src/modality.ts`, REQ-026h) — both are R5-owned; R4 reads them only if a `fetch_page` path calls them. Config load/validation and provider dispatch tables (R2 closed); §6.3 provider conventions (R2 closed). Release, credentials, and schema migration (none touched). Defects that violate only a **non-R4** REQ — `REQ-004` truncation mechanism, `REQ-001` envelope, `REQ-035`/`REQ-032` timeout/retry, `REQ-107` routing citations outside `fetch_page` — are not filed as R4 rows; they are recorded as a cross-chunk note naming the owning closed chunk and dispositioned under D41.

  - Split only when the Phase 1 **enumeration** records more than 120 distinct `file:line` anchors, or when four or more clusters each need a live probe. The count is of enumerated anchors, not of verdict cells (which do not exist until Phase 2).
  - A **leg** is the named subset of a cluster's review-surface row that a REQ depends on; the cluster table marks each leg by its REQs and files.
  - **R4a** = clusters A–B whole (A: transport/safety; B: renderer chain and fallback), cluster C's cache/date leg, and cluster F's schema/registration and §6.4 leg.   - **R4b** = cluster C's crawl/extract leg, clusters D–E whole (passages, raw/batch contract, structured facts), and cluster F's raw/batch metadata leg. REQs: `REQ-021b`, `REQ-021d`, `REQ-021e`, `REQ-021i`, `REQ-021j`, `REQ-021k` (6).
  - Every REQ and every cluster leg belongs to exactly one side; groups A–B and D–E are not divided, C and F are divided by leg. At an R4a close the done bar applies to R4a's subset, the status board gains R4a/R4b rows in place of R4, and the successor trigger is R4b, not R5.
  - **Split execution gate (after step 10):** if `split: triggered`, Phase 2 runs only R4a's legs (steps 11, 12, the cache/date half of 13, the REQ-021 final verdict + schema/§6.4 half of 16, and step 17's gate-assertion check restricted to R4a's carrying gates); the crawl/extract half of 13, steps 14, 15, the raw/batch half of 16, and step 18's crawl/extract/raw probe legs are deferred to R4b and marked `deferred:R4b`. - **D36 — Cross-chunk dedup.** Open findings from R1/R2/R3 that touch the `fetch_page` path are **not re-filed**: F-R2-34 (rate-limited `fetch_page` omits `retry_after_ms`) and F-R2-31 (timeouts not retryable, affecting REQ-021's fallback-on-error leg). They stay owned by their chunk; R4 cites them in the predicate cell where a verdict depends on them. A **new** violation of an R4-owned REQ gets its own R4 ID even when the same line is already named by an earlier finding.
- **D37 — Citation resolution.** Classify `_Check:_` first (worklist calibration rule 1). `REQ-021` is G0+G1 and requires the live advertised schema (parameters, defaults, descriptions) plus behavior evidence; `src/tool-surface.test.ts` covers the schema half. The remaining 11 are G1 and require a cited test that exercises the stated behavior, not merely names the REQ (calibration rule 2). A missing citation is only a finding for a G1 REQ with no test exercising the clause.
- **D38 — State and network isolation.** Every live probe (loopback included) runs with a temp `TMPDIR`, a temp `INFOBROKER_CONFIG_LOCAL`, and a temp KB storage path; no probe mutates the real KB, quota file, or user config layer. The loopback probe sets `fetch.allow_private_urls=true` so the fixture is reachable; because that switch also permits a private redirect target, the **redirect re-guard refusal** is proved by a unit test using a resolver stub with `allowPrivate=false` (the `url-guard.test.ts` pattern), not by the probe. Outbound fetch is best-effort: the deterministic preference is debate-club Arena replay, the module tests, and the loopback fixture; an outbound probe that is blocked, throttled, or times out is recorded `NOT_RUN` with the reason, never inflated into a finding.
- **D39 — Prose ownership and boundary.** R4 owns §6.4 only. §6.3 provider conventions and §7.2 dispatch rows were reviewed by R2 and are read as evidence. R3 adjudicated the `structured_fact` classification sentence under `REQ-020a`; **`REQ-021i`'s own classification clause** ("`search_web` SHALL classify it as a `structured_fact` query") is R4's, because the worklist assigns `REQ-021i` to R4. R4 judges the classification through its observable effect — a measurable-attribute query yields the fact object — and does not re-review `src/task-type.ts` as a routing surface. `task-type.test.ts:55-67` exercises the `REQ-021i` classification explicitly but its `@implements` header cites only `REQ-020a`; Phase 2 reads it as behavior evidence. Calibration rule 2 clears the citation (a test does exercise the clause); calibration rule 5 separately decides whether the missing `REQ-021i` tag is a finding.
- **D40 — No push.** Publication stays user-authorized.
- **D41 — Non-R4 defect disposition.** A defect found while reviewing the fetch path that violates only a non-R4 REQ (`REQ-001`, `REQ-004`, `REQ-031`, `REQ-032`/`REQ-035`, `REQ-107`) is recorded in the AAR as a cross-chunk note naming the owning chunk and its state (closed or scheduled), with a `file:line` predicate. It is not added to the R4 finding register and does not change an R4 verdict. If it is a regression of a resolved R1 fix (D36), it becomes an R4 finding because the fetch path is the observed surface.

- **Live fetch dependence.** Outbound fetch may be blocked or throttled. Mitigated by Arena replay, module tests, and a loopback fixture with `allow_private_urls=true`; blocked outbound probes recorded `NOT_RUN` (D38).
- **Shared modules.** `rerank.ts` is used by R3 and R6; `structured-fact.ts` is used by R5 (EV11). Splitting ownership wrongly would double-count findings. Mitigated by D39/D41/EV11 and by filing only violations of R4-owned REQs.
- **Tracker drift.** The R4 code line names two R5 modules and omits several reviewed files. Mitigated by EV10 and the exhaustive correction in step 20.
- **Finding volume.** R3 produced a finding for every REQ. If R4 does the same, the disposition step grows; the P2 rule (fix only on demonstrated failure) and the split rule keep it bounded.
- **P0 overrun.** A P0 exceeding D33's bound stops the chunk with `LOOP OPEN` rather than an unbounded fix.
- **Renderer race semantics.** `fetchPageContent` (`src/index.ts:810-953`) contains a hedge branch at `:890-916` gated on `hedge_enabled && renderers.length > 1`, and `hedge.ts`/`hedge.test.ts` implement the race. Whether the grace window and primary preference match `REQ-021` is a Phase 2 verdict, not a pre-judged P1.
