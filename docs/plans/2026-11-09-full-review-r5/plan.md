## Decisions

- **D42 — Fix policy and split rule.** P0 fixed in-session within at most **two files total** and 100 changed lines, one attempt; exceeding it or failing to reach green lands `LOOP OPEN`. The permitted shapes are: one source file plus its regression test; or one non-behavior-changing source file; or, for a wrong committed benchmark threshold or gold-set expectation, one data file plus the test assertion that pins it (no source change). P1 scheduled on `ROADMAP.md`; P2 fixed only on a demonstrated failure; P3 record-and-close. A defect whose only correct fix is a **config value** is not fixed in-session: it is dispositioned `Scheduled-roadmap` (P1) with a D48 note, because the config surface belongs to R2 and a config edit is out of this chunk's blast radius.
  - **Split threshold.** Split only when Phase 1 records **more than 120 distinct enumerated anchors**, or **four or more clusters are probe-dependent**. A *distinct anchor* is one unique `file:line` after de-duplication **across** clusters, where a range counts once. A *probe-dependent* cluster is one whose REQs turn on runtime behavior that no existing test, fixture, or gate observes, so a verdict needs the step 11 probe. Step 5 records the per-cluster probe-dependence with the reason; step 10 records `split: triggered | not triggered`.
  - **R5a** = clusters A, B, D, G. REQs: `REQ-026`, `REQ-026a`, `REQ-026b`, `REQ-026e`, `REQ-026f`, `REQ-026g`, `REQ-121`, `REQ-123` (8). **R5b** = clusters C, E, F. REQs: `REQ-026c`, `REQ-026d`, `REQ-026h`, `REQ-122`, `REQ-027`, `REQ-027a`, `REQ-130` (7). Clusters are never divided; the union is exactly 15.
  - **Split execution gate (after step 10).** If triggered, Phase 2 runs only steps 12, 13, 15, 18, 19 and probe legs (a), (b), (c), (f); steps 14, 16, 17 and probe legs (d), (e) are marked `deferred:R5b`. Phase 3 dispositions R5a findings only; step 19 covers R5a's carrying gates only; step 21 corrects both R5a and R5b code lines from one enumeration; the status board gains R5a/R5b rows in place of R5; the successor trigger is R5b.
- **D43 — Cross-chunk dedup.** Open findings from closed chunks are not re-filed: F-R2-14 (`verify_claims.providers` bypasses the disabled-provider rule) and F-R2-31 (timeouts not retryable) stay R2-owned and are cited in the predicate cell. A **new** violation of an R5-owned REQ at the same line gets its own R5 ID, following the `F-R5-<cluster letter>-<n>` pattern.
- **D44 — Citation and evidence class.** Classify `_Check:_` first (worklist calibration rule 1). `REQ-026` and `REQ-027` are G0+G1 and require the live advertised schema plus behavior evidence; the other 13 are G1 and require a cited test that exercises the stated clause (calibration rules 2–3). Every verdict predicate cell opens with its evidence class — `test:`, `gate:`, `static:`, or `probe:`. A G1 REQ's clause supported only by `static:` reading is a finding, not a `holds`, because no test exercises it.
- **D45 — State and network isolation.** Every live probe runs under a fresh `/tmp/opencode/r5-probe/` (removed and recreated before use) with a temp `TMPDIR`, a temp `INFOBROKER_CONFIG_LOCAL`, and a temp KB storage path; no probe mutates the real KB, quota file, or user config layer. `verify_claims` is network-dependent by construction: the deterministic preference is module tests, the committed fixtures, and the debate-club Arena replay. An outbound leg that is blocked, throttled, or timed out is recorded `NOT_RUN` with the reason. `NOT_RUN` may not be claimed for a leg the loopback fixture can serve.
- **D46 — Prose ownership.** R5 owns §1 goal 4, §3 SR-008, §5.5, and §8.1–§8.3, per the worklist prose-ownership table (`worklist.md:87,98`) and the R5 coverage row. §6.2 envelope, §6.3 provider conventions, §7.x dispatch, §9.5 manifest rows belong to other chunks and are read as evidence. The §8.1 pseudocode is judged as a contract sketch — does `src/corroborate.ts` match its claims — not as implementation detail.
- **D47 — Fixture determinism.** `REQ-130`'s benchmark must run deterministically without network: `runBenchmark(cases, k = 5)` takes a fixed default `k` (`src/retrieval-benchmark.ts:108`), and the scoring path imports `reconcileResults` from `dedup.js` with no fetch module. R5 verifies that structurally and runs the suite **twice** in one session, requiring identical metrics. `REQ-123`'s gold set is likewise deterministic (`scripts/calibrate-confidence.ts` header: "No network, no clock-dependent output").
- **D48 — Non-R5 defect disposition.** A defect found on this surface that violates only a non-R5 REQ is recorded in the AAR as a cross-chunk note naming the owning chunk and its state, with a `file:line` predicate. It is not added to the R5 register and does not change an R5 verdict.
- **D49 — No push.** Publication stays user-authorized.
